# Reproduction: Which Command Produces Which Number

Terminology: [../README.md](../README.md).

This file lists, for every number reported in the paper, the command that
produces it and the file it lands in. Outputs are written under `outputs/` and
are **not** tracked by git; every one of them is regenerated by the commands
below.

Each command runs from the repository root with `PYTHONPATH=.`:

```bash
PYTHONPATH=. python -m <module>
```

## 0. Data

Raw datasets are not kept in the repository; see
the README's Datasets section for how to download them, and
for the three scripts that build the ChEMBL target features. The split lists
(`data/raw/gin_v2_*_ids.json`) and the descriptor normalizers **are** in the
repository and must not be deleted: without them the splits are regenerated
and the reported numbers change.

## 1. The three split families

Results are comparable **only within a split family**.

| Split | Test set | Purpose | Environment variable |
|---|---|---|---|
| **Scaffold-204** | 204 molecules | Our ablation table (A1–A5) | (default) |
| **OGB/Hu scaffold** | 143 molecules | Like-for-like with the literature (Hu et al. 2020) | `HELDOUT_SPLIT=ogb_scaffold` |
| **Random 80/10/10** | 143 molecules × 3 partitions | MoleculeNet-style comparison; mean ± std | `HELDOUT_SPLIT=random RANDOM_SPLIT_SEED=0..2` |

GNN scripts select the split through the config (`dataset.heldout_split`,
`dataset.random_split_seed`); the classical-model and blend scripts use the
environment variables.

## 2. GIN-v2 ablation (scaffold-204)

Model names follow the paper; the `outputs/` tags keep the original
experiment numbering (A1 = `2_1`, A2 = `2_2`, A3 = `2_3`, A4 = `2_5`,
A5 = `2_6`, A3+A5 = `karma_scaffold`). Each row is 5 seeds; the reported
number is the 5-seed ensemble.

| Paper name | Training script (`python -m ...`) | Tag |
|---|---|---|
| Baseline | `scripts.train.scaffold204_baseline` | `baseline` |
| A1 capacity (5 layers, width 300) | `scripts.train.scaffold204_a1_capacity` | `2_1` |
| A2 asymmetric loss | `scripts.train.scaffold204_a2_asl` | `2_2` |
| A3 RDKit descriptors | `scripts.train.scaffold204_a3_descriptors` | `2_3` |
| A4 uncertainty weighting | `scripts.train.scaffold204_a4_uncertainty` | `2_5` |
| A5 SWA | `scripts.train.scaffold204_a5_swa` | `2_6` |
| A3+A5 combined | `scripts.train.scaffold204_a3a5` | `karma_scaffold` |

Each script takes optional seed indices (default `0 1 2 3 4`). Evaluation of
the 5-seed ensemble on the held-out test set (the checkpoint prefix is
`outputs/ensemble_hetero/ginv2_<tag>_`; A3 and A3+A5 also need
`ablation.use_rdkit_descriptors=true`, and A3+A5 and A5
`ablation.use_swa=true`):

```bash
PYTHONPATH=. python -m scripts.eval.ensemble \
  outputs/ensemble_hetero/ginv2_baseline_ baseline
PYTHONPATH=. python -m scripts.eval.ensemble \
  outputs/ensemble_hetero/ginv2_2_3_ 2_3 ablation.use_rdkit_descriptors=true
```

The single-checkpoint scorer `scripts.eval.single_checkpoint` evaluates one
model; it is used for per-seed numbers.

| Model | Macro-AUC | Output (`outputs/eval/ginv2_heldout_ensemble_*`) |
|---|---|---|
| Baseline | 0.568 | `baseline.json` |
| A1 | 0.547 | `2_1.json` |
| A2 | 0.589 | `2_2.json` |
| A3 | 0.620 | `2_3.json` |
| A4 | 0.577 | `2_5.json` |
| A5 | 0.600 | `2_6.json` |
| A3+A5 | 0.622 | `karma_scaffold.json` |

## 3. Classical models (all three splits)

One script; model and feature set are given as arguments.

```bash
python -m scripts.eval.classic rf:ecfp_rdkit        # scaffold-204
HELDOUT_SPLIT=ogb_scaffold python -m scripts.eval.classic rf:ecfp_rdkit
HELDOUT_SPLIT=random RANDOM_SPLIT_SEED=0 python -m scripts.eval.classic rf:ecfp_rdkit
```

Feature sets: `ecfp` (ECFP4, 2048 bits), `ecfp_rdkit` (+217 RDKit 2D
descriptors), `ecfp_rdkit_target` (+101 ChEMBL target features),
`ecfp_rdkit_aux` / `ecfp_rdkit_auxsmall` (+auxiliary-task stacking, see §5).
Models: `rf`, `hgb`, `xgb`.

| Model | Scaffold-204 | OGB/Hu | Random (mean ± std) |
|---|---|---|---|
| RF, ECFP | 0.606 | 0.659 | 0.672 ± 0.019 |
| **RF, ECFP + RDKit** | **0.616** | **0.678** | **0.680 ± 0.018** |
| RF, + ChEMBL targets | 0.617 | — | — |
| XGBoost, ECFP + RDKit | 0.605 | 0.665 | 0.672 ± 0.015 |
| HGB, ECFP + RDKit | 0.599 | — | — |

Tags are `classic_{model}_{features}` plus a split suffix (`_ogb`,
`_random_seed{N}`).

## 4. Like-for-like split with the literature (OGB/Hu)

```bash
python -m scripts.train.ogb_baseline 0 1 2 3 4    # baseline
python -m scripts.train.ogb_a3       0 1 2 3 4    # A3  (run first: fits the normalizer)
python -m scripts.train.ogb_a3a5     0 1 2 3 4    # A3+A5
python -m scripts.train.ogb_a3       5 6 7 8 9    # seeds 1005-1009 (10-seed protocol)
```

Evaluation passes `dataset.heldout_split='"ogb_scaffold"'` and, for A3 and
A3+A5, `dataset.rdkit_descriptor_normalizer_path='"data/raw/ginv2_rdkit_descriptor_normalizer_ogb.json"'`
(the normalizer is fitted on this split's training molecules). Per-seed scores
use `SEED_INDICES=<i>`, the 10-seed ensemble `N_SEEDS=10`. The exact calls are
in `scripts/run/remaining_experiments.sh`, which runs the whole OGB/Hu and
random-split queue.

| Model | Macro-AUC | Output (`ginv2_heldout_ensemble_*`) |
|---|---|---|
| Baseline GIN, 5 seeds | 0.558 (95% CI 0.499–0.620) | `baseline_ogb.json` |
| A3, 5-seed ensemble | 0.632 | `2_3_ogb.json` |
| A3, mean over 5 seeds | 0.624 ± 0.009 | `2_3_ogb_seed100{0..4}.json` |
| A3, 10-seed ensemble | 0.626 (AUPR 0.653; vs RF −0.052, p = 0.032) | `2_3_ogb_10seed.json` |
| A3+A5, 5-seed ensemble | 0.629 | `karma_ogb.json` |
| A3 + RF blend (5 / 10 seeds) | 0.673 / 0.669 (10 seeds: AUPR 0.675) | `blend_2_3_rf_ogb.json`, `blend_2_3_rf_ogb_10seed.json` |

The mean over seeds is computed from the `macro_auc` field of the single-seed
JSON files (population standard deviation, ddof=0). Seeds 1005–1009 give the
10-seed protocol of Hu et al.

## 4b. Random 80/10/10 splits (three partitions)

The combined A3+A5 model on partitions 0, 1 and 2 (split 0 keeps the original
names, splits 1 and 2 carry `_s1` / `_s2`):

```bash
for N in 0 1 2; do
  RANDOM_SPLIT_SEED=$N python -u -m scripts.train.random_a3a5 0 1 2 3 4
done
# per partition (N=1,2; partition 0 omits the _sN suffix):
REF_TAG=classic_rf_ecfp_rdkit_random_seed$N python -m scripts.eval.ensemble \
  outputs/ensemble_hetero/ginv2_karma_random_s${N}_ karma_random_s$N \
  ablation.use_rdkit_descriptors=true ablation.use_swa=true \
  dataset.heldout_split='"random"' dataset.random_split_seed=$N \
  dataset.rdkit_descriptor_normalizer_path='"data/raw/ginv2_rdkit_descriptor_normalizer_random_seed'$N'.json"'
python -m scripts.eval.blend karma_random_s$N classic_rf_ecfp_rdkit_random_seed$N blend_karma_rf_random_s$N
```

| Model (macro-AUC) | Partition 0 | Partition 1 | Partition 2 | Mean ± std |
|---|---|---|---|---|
| A3+A5 ensemble | 0.679 | 0.654 | 0.678 | 0.670 ± 0.012 |
| RF, ECFP + RDKit | 0.670 | 0.665 | 0.705 | 0.680 ± 0.018 |
| A3+A5 + RF blend | 0.687 | 0.670 | 0.701 | 0.686 ± 0.013 |

Paper table `tab:random` (random 80/10/10 splits) is built from these JSON
files. Macro-AUPR and the paired bootstrap comparison against the RF of the
same partition (`vs_baseline` field of the GIN JSON, 2000 resamples):

| Partition | GIN macro-AUPR | Blend macro-AUPR | GIN − RF, AUC (p) | GIN − RF, AUPR (p) |
|---|---|---|---|---|
| 0 | 0.693 | 0.701 | +0.009 (p = 0.51) | +0.006 (p = 0.62) |
| 1 | 0.693 | 0.719 | −0.011 (p = 0.48) | −0.028 (p = 0.021) |
| 2 | 0.670 | 0.698 | −0.027 (p = 0.086) | −0.030 (p = 0.086) |

The blend JSONs carry no `vs_baseline` block. The effect of the split family
on the same model (paper table `tab:spliteffect`) compares the A3 / RF rows of
§2–§4 across scaffold-204, OGB/Hu and random partitions; nothing is retrained
for it.

Outputs: `ginv2_heldout_ensemble_karma_random[_s1|_s2].json` and
`ginv2_heldout_ensemble_blend_karma_rf_random[_s1|_s2].json`. Paired
comparisons are made only within the same partition; the mean ± std over
partitions is the population standard deviation.

## 5. Auxiliary data: multi-task for the GNN, stacking for the RF

The GNN uses the auxiliary datasets (Tox21, ClinTox, BBBP, HIV, MUV) through
multi-task training: one shared encoder with extra output columns
(`configs/default.yaml` → `dataset.aux_datasets`; code in
`src/train.py::build_combined_train_set`).

The classical counterpart is stacking: one RF per auxiliary task, whose
predicted probabilities for the SIDER molecules become extra features for the
SIDER RF.

```bash
python -m scripts.analysis.build_rf_aux_stack       # 33 auxiliary-task RFs, ~1 hour
sh scripts/run/rf_aux.sh                   # all splits, then the comparison
```

Leakage control: every SIDER molecule (train, stopping slice and test) is
removed from the auxiliary training sets, matched on the InChIKey connectivity
block of the largest fragment. Overlap removed: Tox21 1057, ClinTox 1046, BBBP
566, HIV 205. This makes the auxiliary models independent of the split, so the
feature matrix is built once and reused for every split.

| Comparison | Plain RF | RF + auxiliary | Difference (paired bootstrap) |
|---|---|---|---|
| Scaffold-204 | 0.616 | 0.613 | −0.003 (p = 0.74) |
| OGB/Hu | 0.678 | 0.693 | +0.015 (p = 0.040) |
| Random (3 partitions) | 0.680 | 0.686 ± 0.020 | +0.006, none individually significant |

In short: auxiliary data does not significantly raise the RF. The only nominal
gain is on the OGB/Hu split, one of five comparisons, with no
multiple-comparison correction. Output: `outputs/eval/rf_aux_comparison.json`.

**Note on the protocol difference.** The GNN's auxiliary protocol is looser:
it uses all molecules of the auxiliary datasets, including those overlapping
the SIDER test set. Since those molecules carry no SIDER labels this is not
leakage, but it is not as strict as the RF setup either, so the RF measurement
may understate what auxiliary data contributes.

## 6. GNN + RF blend

No training: the equally weighted average of the two models' stored test
probabilities. The weight is fixed in advance (0.5/0.5) and never chosen on
the test set.

```bash
python -m scripts.eval.blend 2_3 classic_rf_ecfp_rdkit blend_2_3_rf        # A3 + RF
python -m scripts.eval.blend 2_3_ogb classic_rf_ecfp_rdkit_ogb blend_2_3_rf_ogb
```

| Blend | Scaffold-204 | OGB/Hu |
|---|---|---|
| A3 + RF | 0.631 | 0.673 |
| A3+A5 + RF | 0.631 | — |
| A3 + (RF + auxiliary) | 0.630 | 0.678 |

On OGB/Hu the blend clearly beats the GNN alone (+0.046, p < 0.001) but does
not significantly beat the RF on any split.

### Strongest model: GIN + RF blend on every split family

The blend column of paper Table A.10 / the "strongest model" uses these
components (5-seed GIN ensemble, RF ECFP4 + RDKit, weights 0.5 / 0.5):

| Split | GIN component | RF component | Blend tag | Macro-AUC |
|---|---|---|---|---|
| Scaffold-204 | A3+A5 (`karma_scaffold`) | `classic_rf_ecfp_rdkit` | `blend_karma_rf` | 0.631 |
| OGB/Hu | **A3** (`2_3_ogb`) | `classic_rf_ecfp_rdkit_ogb` | `blend_2_3_rf_ogb` | 0.673 |
| Random 0 / 1 / 2 | A3+A5 (`karma_random[_s1\|_s2]`) | `classic_rf_ecfp_rdkit_random_seed{0,1,2}` | `blend_karma_rf_random[_s1\|_s2]` | 0.687 / 0.670 / 0.701 |

The OGB/Hu blend of the paper uses A3 while the other two families use A3+A5.
To blend the same GIN variant everywhere, `blend_karma_rf_ogb`
(`karma_ogb` + `classic_rf_ecfp_rdkit_ogb`; the checkpoints exist, GIN
0.629) can be produced with no new training:

```bash
python -m scripts.eval.blend karma_ogb classic_rf_ecfp_rdkit_ogb blend_karma_rf_ogb
```

`scripts/run/best_blend.sh scaffold | ogb | random N` runs training,
evaluation and blend for one family in one place (`TRAIN=0` re-uses existing
checkpoints; `EVAL_OUT_DIR=...` writes elsewhere). The A3 recipe behind
`blend_2_3_rf_ogb` is in §4 and §6 above.

## 7. Statistics

All comparisons live in `src/eval_metrics.py`:

- `bootstrap_ci` — 95% confidence interval from 2000 bootstrap resamples.
- `paired_bootstrap_pvalue` — two-sided paired bootstrap p-value for the
  difference between two models on the same molecules (molecules are resampled
  with a shared index, so the pairing is preserved).
- On the random split, paired comparisons are made only within the same
  partition; differences across partitions are reported as mean ± std.

No multiple-comparison correction is applied, so individual p-values should be
read as exploratory.

## 8. Reproducibility verification

The paper-facing Tier 1 verification covers the stored GIN ensembles, the
ECFP4+RDKit RF on all three split families, and the GIN+RF blends. It
re-evaluates GIN checkpoints, retrains the classical models, and recomputes
blends in a separate output directory so the original results remain intact:

```bash
systemd-inhibit --what=idle:sleep:shutdown --mode=block \
  --why='Running paper reproducibility checks' \
  env PYTHONPATH=. python -m scripts.analysis.reproducibility_test --tier 1
```

The verification was run in the project's reproducible Python environment
with the host sleep inhibitor enabled. Stored GIN checkpoint re-evaluation
passed; the RF and
dependent blend checks can report FAIL because retraining a Random Forest
does not guarantee bit-identical probabilities across library/runtime
execution paths, even with `random_state=0`. The report is written to
`outputs/eval_repro/repro_report.csv` and
`outputs/eval_repro/repro_endpoint_auc.csv`; a FAIL here is an exact
reproducibility warning, not evidence that the model or split is invalid.

The latest Tier 1 rerun produced these macro-AUC values:

| Model | Scaffold-204 | OGB/Hu | Random mean |
|---|---:|---:|---:|
| RF, ECFP4 + RDKit | 0.615 | 0.678 | 0.680 |
| GIN (A3+A5) | 0.622 | 0.629 | 0.670 |
| GIN (A3+A5) + RF | 0.631 | 0.672 | 0.686 |

These are verification values from retraining and re-evaluation; the paper
tables continue to use the original held-out outputs unless explicitly
regenerated from the verification directory.
